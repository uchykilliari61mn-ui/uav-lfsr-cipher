# Шифратор кадру для відеопередачі з дрона (LFSR block scrambling)

Реалізація на C++ алгоритму шифрування зображення зі статті:

> **Low Cost Analog Video Transmission Security of Unmanned Aerial Vehicle (UAV)
> based on Linear Feedback Shift Register (LFSR)**
> Heri Suryoatmojo, Fery Setiawan, Ronny Mardiyanto, Astria Nur Irfansyah.
> *2021 International Seminar on Intelligent Technology and Its Applications (ISITIA).*
> DOI: 10.1109/ISITIA52817.2021.9502241

Шифрується статична картинка (кадр відео). Реалізовано зашифрування та
розшифрування.

## Ідея методу

Дешеве рішення для захисту аналогового відео з дрона: кадр не шифрується
«по пікселях», а **розбивається на блоки, які перемішуються** за псевдовипадковою
перестановкою. Перестановка задається **16-бітним LFSR**, а його початкове
значення (**seed**) виконує роль **ключа**.

```
Оригінал ──► поділ на сітку rows×cols блоків ──► перестановка блоків за LFSR ──► зашифрований кадр
                                                        ▲
                                                   seed (ключ)
```

- Однаковий seed на передавачі (дрон) і приймачі (наземна станція) дозволяє
  відновити кадр.
- Різні seed дають різні «малюнки» перемішування (у статті порівнюються
  seed 44257, 1234, 1111).

## Чому саме такий LFSR

У статті для прикладу використано **seed 44257**. Це значення дорівнює
`0xACE1` — канонічному початковому стану 16-бітного LFSR Фібоначчі з відводами
**16, 14, 13, 11**. Саме цей регістр і реалізовано:

```
feedback = b0 XOR b2 XOR b3 XOR b5
lfsr     = (lfsr >> 1) | (feedback << 15)
```

Послідовність станів LFSR подається у тасування Фішера–Єйтса, яке будує
**таблицю перестановок** блоків (бієкцію без колізій). Завдяки детермінованості
LFSR та сама таблиця точно відтворюється за тим самим seed, тож розшифрування
застосовує її у зворотному напрямку.

## Структура

| Файл | Призначення |
|---|---|
| `lfsr.h` | 16-бітний LFSR і побудова таблиці перестановок |
| `cipher.h` | поділ кадру на блоки та їх перемішування (encrypt / decrypt) |
| `main.cpp` | CLI: завантаження PNG/JPG, виклик шифру, збереження PNG |
| `third_party/` | `stb_image` / `stb_image_write` (public domain, читання/запис зображень) |
| `demo.sh` | показова прогонка: оригінал → шифр (3 seed) → дешифр |

Зовнішніх бібліотек не потрібно — лише `stb` (вже в репозиторії).

## Збірка

```bash
g++ -std=c++17 -O2 -o uav_cipher main.cpp
```

## Використання

```bash
# Зашифрувати (сітка за замовчуванням 3×4 = 12 блоків, як у статті)
./uav_cipher encrypt frame.png encrypted.png 44257

# Розшифрувати тим самим seed
./uav_cipher decrypt encrypted.png restored.png 44257

# Інша сітка: rows cols (у статті згадано до 12×16)
./uav_cipher encrypt frame.png encrypted.png 1234 12 16
```

Параметри: `<режим> <вхід> <вихід> <seed> [rows] [cols]`.

Якщо розміри кадру не кратні сітці, зайві пікселі з правого/нижнього краю
обрізаються (у статті приймач теж обрізає кадр через video grabber).

## Демонстрація

```bash
./demo.sh
```

Скрипт шифрує `sample.png` трьома різними seed і розшифровує назад.
Результат: зашифровані кадри виглядають як перемішаний «пазл», а розшифрований
**піксель-у-піксель** дорівнює оригіналу.

## Відповідність статті та відмінності

- Метод (block scrambling за LFSR-перестановкою, seed як ключ, обернення на
  прийомі) відтворено точно.
- LFSR 16-біт з відводами 16/14/13/11 обрано за збігом seed 44257 = 0xACE1.
- Спосіб перетворення послідовності LFSR у перестановку (Фішер–Єйтс) обрано як
  коректний і відтворюваний; у статті він детально не специфікований.
- Шифрується статичний кадр (як і дозволено умовою лабораторної); для відео
  той самий процес застосовується покадрово.

## Безпека (для подальшого обговорення зламу)

Метод приховує лише **розташування** блоків, але не змінює їх вміст. Тому він
вразливий до:
- **атаки на основі вмісту** — блоки неба/поля легко впізнати й зібрати «пазл»
  назад без ключа;
- **малого простору ключів** — 16-бітний seed це лише 65 535 варіантів, перебір
  миттєвий;
- **відсутності дифузії** — статистика кольорів кадру не змінюється (кореляція
  гістограм лишається високою).

Напрямки вдосконалення: більше блоків, додавання підстановки (XOR/перестановка
пікселів усередині блоку), ширший ключ, зміна seed покадрово.
